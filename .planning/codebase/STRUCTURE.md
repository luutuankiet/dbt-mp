## Directory Purposes

**`dbt_mp/`:**
- Purpose: The primary Python package containing the application's source code.
- Contains: The main script and any future modules.
- Key files: `dbt_mp/main.py` is the most important file, containing the entire logic.

**`target/` (Generated):**
- Purpose: This is the default output directory for `dbt`. This application reads the `manifest.json` file from this directory. It is not part of the application's source code but is essential for its operation.
- Contains: Compiled dbt models, logs, and the `manifest.json`.
- Key files: `target/manifest.json`.

## Key File Locations

**Entry Points:**
- `dbt_mp/main.py`: Contains the `main()` function which is the script's entry point. The CLI tool `dbt-mp` is mapped to this function in `pyproject.toml`.

**Configuration:**
- `pyproject.toml`: Defines project metadata, dependencies (`python-semantic-release`), and configures the `dbt-mp` command-line script.

**Core Logic:**
- `dbt_mp/main.py`: All logic for parsing arguments, running `dbt` subprocesses, filtering the manifest, and writing the output file resides here.

**Testing:**
- No test files or testing structure were detected in the codebase.

## Naming Conventions

**Files:**
- `snake_case`: Python files like `main.py` follow standard Python conventions.

**Directories:**
- `snake_case`: The main package `dbt_mp` follows Python package naming conventions.

**Functions & Variables:**
- `snake_case`: Functions (`run_dbt_ls`, `slim_node`) and variables (`slim_manifest`, `selected_unique_ids`) follow PEP 8 conventions.

## Where to Add New Code

**New Feature:**
- Primary code: New functions should be added to `dbt_mp/main.py`. If the tool's complexity grows, new logic could be factored out into new files within the `dbt_mp/` directory (e.g., `dbt_mp/parser.py`, `dbt_mp/dbt.py`).

**New Component/Module:**
- Implementation: If a new logical component were added (e.g., a different output format), it would likely start as a new function in `dbt_mp/main.py` and could be moved to a new file like `dbt_mp/formatting.py` if it became large.

**Utilities:**
- Shared helpers: Any new helper functions would be added directly to `dbt_mp/main.py`.

## Special Directories

**`target/`:**
- Purpose: Contains dbt-generated artifacts. This application is a *consumer* of this directory, not its owner.
- Generated: Yes, by running `dbt compile` or `dbt run`.
- Committed: No, this directory should be included in `.gitignore`.

**`.egg-info/`, `dist/`:**
- Purpose: Packaging and distribution artifacts generated by `setuptools` when building the project.
- Generated: Yes, by running packaging commands (e.g., `pip wheel`).
- Committed: No, these should be in `.gitignore`.
